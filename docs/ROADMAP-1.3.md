# HuangNotify 1.3.0 更新規劃

狀態：規劃完成，待實作與驗證。規劃日期：2026-11-02（台灣）。
基準：1.2.0 正式版；程式來源 `527a0f18091d209fce11debee02d8d38be73ce18`，文件基準 `3d5502e68f04ab2484ecbffbfaf7fe180ec5498f`。

定位：優先縮短備份等待時間，改善大型備份的操作延續、漏記排查與舊通知查找。預定正式版號 1.3.0，versionCode 在實作時核對最新正式版後遞增。維持免費、無廣告、無帳號、MIT 開源。

## 備份速度優化（P0）

使用者回報 1.2.0 備份過慢。以下為程式碼檢查後的優先量測與實作方向，尚未證實哪一項是該手機上的主要瓶頸，亦未宣稱已完成加速。

### 先建立分段基準

分開記錄等待作業／資料庫佇列、WAL checkpoint 與快照複製、SQLite 查詢與 JSON／Base64 輸出、密碼金鑰導出、加密、目標位置寫入、讀回驗證及清理耗時。報告同時列出通知／歷程／唯一圖片數、JSON bytes、容器 bytes、DB 實體大小與峰值記憶體，不記錄通知正文或密碼。

手動選擇檔案位置所花的時間獨立排除，App 內等待及檔案提供者讀寫時間仍須呈現。先以本機檔案提供者作可重現比較，再分開驗證雲端位置，不混用兩者宣稱加速。

### 優先改善項目

| 項目 | 目前流程觀察 | 改善方向 |
| --- | --- | --- |
| 匯出與加密 | 加密匯出先產生完整 plain.json，接著讀取並加密成 output.hnbk | 讓逐筆 JSON 直接進入有界分段加密輸出，減少一份完整明文檔的寫入與讀取；完成末尾驗證區塊後才標示準備完成，失敗清除作業暫存 |
| 校驗碼計算 | 手動及自動備份在複製前完整讀取 ready 檔計算 SHA-256 | 在最終備份檔生成時同步計算最終 bytes 的 SHA-256 與長度，保存於該作業記憶體；複製後仍關閉輸出並讀回目標檔比對，保留完整性保障 |
| 通知與圖片查詢 | 每筆通知另外查歷程，每筆通知／歷程另外查圖片引用 | 以有界批次或依序游標減少逐筆 SQL 往返；保留通知／歷程順序與共用圖片去重，不把整份備份載入記憶體 |
| 快照成本 | 目前複製完整資料庫檔案，刪除後的可重用空間也可能增加複製量 | 同時量測大量刪除前後的 DB 實體大小、checkpoint 與複製耗時；替代方案以一致性、通知寫入延遲及暫存用量共同驗收 |
| 加密與緩衝 | HNBK2 每 64 KiB 建立 frame，現行流程會配置 Cipher 與小型 buffer | 量測 provider 初始化及配置成本，再評估安全重用物件與調整 I/O 緩衝；維持既有 64 KiB frame 上限、獨立 nonce、AAD、終止區塊與固定 KDF 參數 |

圖片 hash 查詢已有索引，先檢查查詢計畫與實測，不預設問題出在缺少索引。先優化資料路徑，再按量測結果處理其餘成本；不以提高執行緒數作為預設解法，須確認備份期間通知仍可寫入。

### 量測目標與驗收

- 使用可重現的合成資料，比較 1.2.0 與新版：10／50／接近 100 MiB，涵蓋文字為主、圖片為主、大量短通知／歷程，以及大量刪除後資料庫仍大的情境；每種資料均測加密及未加密匯出。
- 同一裝置、同一目的地、相近電量與溫度下，先暖機再至少量測 5 次，列中位數、範圍與各階段耗時；首次執行另列。CI 模擬器與 Samsung A55 的結果分開記錄。
- 工程目標：本機 50／接近 100 MiB 加密備份的 App 內總處理時間，相較 1.2.0 中位數降低至少 30%；10 MiB 備份不出現超過 10% 的中位數退步。這是待驗證目標，實際改善幅度以實測報告為準；未達標須記錄主要剩餘成本並調整實作後再驗收。
- 64 MiB JVM heap 下的 100 MiB 加解密測試保留；Android 另記錄完整匯出／寫入／驗證的峰值記憶體、暫存峰值及通知寫入延遲，不能以大量記憶體或長時間阻塞通知換取表面加速。
- 新版產出的 HNBK2／JSON v3 檔須能由 1.2.0 讀取；新版仍可還原舊備份。保留錯密碼、損壞、截斷、取消、空間不足、文件權限失效及衝突回滾驗證。
- 不降低 PBKDF2 次數、不省略 AES-GCM 驗證或輸出後 SHA-256 讀回比對。自動備份仍在新檔完整驗證成功後才清理舊檔。
- 介面顯示階段、已用時間及可計算的處理進度；剩餘時間只有在量測足夠穩定時才估算，等待外部檔案服務時如實標示。

以上新增項目與原有生命週期、診斷及篩選規劃共同納入 1.3.0；單份 JSON 上限維持 100 MiB。

## 備份作業設計

目前 1.2.0 的 `BackupScreen` 由 Activity 持有，畫面銷毀時會取消作業。下一版先將作業狀態、私有暫存檔、結果與取消旗標移到 App 程序持有的管理元件；畫面只訂閱進度與接收使用者操作。

- 同一作業具唯一識別碼，畫面重建重新連接，舊畫面不再接收回呼。
- 檔案選擇器往返及還原預覽可找回對應作業，避免出現兩次選檔或兩次合併。
- 切到背景時，程序仍存活便可繼續既有作業；取消入口在重新進入後仍可使用。這不保證 Android 不會終止程序。
- 程序被終止後顯示「上次作業已中斷，請重新操作」，清理遺留暫存；手動密碼不落盤，不宣稱可自動接續已失去的加密狀態。
- 還原維持完整驗證後才進入單一交易；成功訊息以交易提交及輸出讀回驗證結果為準。
- 文件提供者未返回的讀寫可能延後取消，介面顯示「正在取消，等待檔案服務回應」，避免提早顯示完成。
- 備份 JSON v3、HNBK2 及 100 MiB 上限維持相容；舊 v1／v2 JSON 與 HNBK1 的還原能力保留。

主要修改範圍：`BackupScreen`、`BackupTask`、`BackupFiles`、`AutoBackup` 與 Activity 結果銜接；先處理生命週期，再接新 UI。

## 通知診斷與 Samsung A55

流程為「開始測試 → 自行操作截圖或來源 App → 回來查看結果」。只分析測試時間內實際送達通知監聽器的事件，依來源套件與處理狀態呈現；不收集通知正文、圖片、通知 key 或相簿內容。

- 沒有事件時只表示本工具未觀察到送達事件，不能直接判定來源沒發通知，也不能宣稱已修好漏記。
- 若是暫停、來源排除、未授權或服務未連線，提供相符的設定入口與說明；重新連線後重新讀取實際狀態。
- 診斷維持最近 200 筆上限；測試區間資料被上限截斷時明確提示，不把不完整資料當作完整測試。
- 關閉診斷會清除紀錄，測試引導不自行開啟診斷或授權。匯出前預覽與確認，使用者自行分享。
- Samsung A55 的實際截圖案例仍待取得可重現的診斷。取得證據後另定相容性修正與回歸案例；本版不能預先列為修復成功。

主要修改範圍：`Diagnostics`、`CaptureService` 的狀態呈現與診斷查詢。現有來源排除、暫停與群組摘要規則須回歸。

## 日期、圖片篩選與清理

日期以首次保存時間為準，與目前「今日新增」口徑一致。起迄日期包含兩端日期，查詢採本機時區的開始日零時到結束日次日零時之前；兩個日期倒置時在視窗內提示。畫面顯示目前條件與清除入口，返回紀錄頁保留當次選擇。

「只看有圖片」指目前或歷程仍有已保存圖片引用的通知；圖片已全部清除或來源沒有提供可讀圖片時不符合。條件使用 SQLite 查詢及現有分批載入，避免先把所有紀錄與圖片載入記憶體。

清理預覽預設排除收藏，包含通知及歷程圖片。預估值計算不再被任何保留項目引用的唯一 blob；真正執行時重新計算並以交易確保一致。顯示「可重用的圖片資料空間」，不保證資料庫實體檔案立即縮小。

主要修改範圍：`MainActivity`、`Store`、自訂篩選及圖片清理視窗。

## UI／UX 驗收

- 沿用自訂開關、圓角視窗、顏色及文字層級；主要動作與取消入口位置一致。
- 作業開始、等待選檔、驗證、取消中、成功與失敗各有明確狀態；不顯示無法計算的總百分比。
- 深色與淺色、小螢幕、橫向、200% 字型及 TalkBack 下，可到達主要按鈕、閱讀錯誤與取消作業。
- 日期、來源、圖片條件可組合並一次清除；無結果時說明目前條件，不誤報紀錄遺失。
- 清理、匯出診斷與還原設定均維持明確確認，無需為一般瀏覽反覆授權。
